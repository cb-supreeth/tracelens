Saved views

Retained failure evidence, not an error rate. Service, API path, method and channel match the same failing segment; user and site match the request. Signature groups may overlap. A successful root response does not establish recovery from other observed failures.

Snapshots are saved on this viewer's machine; their links survive service restarts. Updated agents save large captures in bounded chunks, with a downloadable ZIP archive. Storage limits and omitted details are reported explicitly; nothing is silently evicted. Older browser-only pins remain here: choose Save to viewer to preserve one as a file. These links are local, not public share links.

TraceLens ZIP only, up to 66 MiB including archive overhead. Imports create a new saved capture without contacting services. Archives may contain sensitive captured data.

Find your requestFilters, identity & live updates›

Search the backend API path, which may differ from the page URL. Use Observed service and Outcome to narrow the list. More filters adds user, site, method, channel, duration and trace ID or label. The User / site column identifies the caller when captured.

In Live requests, enter a Request data keyword and press Search or Enter to find captured API parameter names or values and request-body text, including downstream services. Matching is case-insensitive. Other filters narrow the requests searched. Missing, expired or uncaptured data cannot match; the search reports its coverage. Search again for new requests. Keywords are not saved in Saved views.

Expand a Group repeated APIs row to select one request. Its Details shows full IDs, timestamps and captured service segments. Remove an active filter chip or choose Reset filters to broaden the results. Saved views remembers filters, not requests.

Auto-refresh updates the list; Refresh checks once. If the list is held while you inspect it, choose Show latest requests. Request and job tab counts match each tab's filters. The separate retained count includes older or filtered-out captures; open Capture info for details.

Follow the request flowServices, connections & boundaries›

The heading shows the API being traced. In Flow diagram, blue boxes are services, purple boxes are database calls or routing decisions, cyan boxes are cache activity, and orange boxes are queues. Other external boundaries are teal. Click a service to explore its code; click a grouped database routing box to see its recorded events.

A cyan CACHE CALL card represents a captured client boundary. CACHE ACCESS represents a recorded cache-wrapper method when no matching client boundary is available, including in older snapshots. Neither label proves a hit or miss. Choose View calling code to inspect the recorded evidence.

Click a purple DB CALL card to see its grouped SQL executions. Query previews use operation and table names, such as SELECT · ems.features_v2, with client-side duration and outcome. Expand an execution for its SQL and use View calling code to follow recorded context. Details also appear in Code flow and Timeline / source. A SQL CAPTURE LIMIT notice means more queries were not retained. DB routing boxes are pool choices, not executed queries.

ClickHouse queries appear in a DB CALL card too. Expand a query for its recorded SQL and any named bindings. Native-query details distinguish response completion from submission only; their source link opens the boundary event when a reliable caller is unavailable.

SQL and parameter values are separate local opt-ins. When available, details show a reconstructed SQL preview with captured values; the original template and typed bindings remain expandable. Missing or unsupported values stay explicit. This is not exact wire SQL or a replay command. SQL literals and bindings can be sensitive: review snapshots and graph exports before sharing. Result rows are not collected, and a returned query does not establish transaction commit.

The diagram's Fit, − / + and 100% controls stay visible while you scroll inside it. On a DB, cache or queue card, choose View calling code; grouped DB routes have a separate link for each event. This opens the owning service's recorded timeline and highlights the nearest reliable calling context. If source was not captured, you see the boundary event instead. Open local source offers editor links when a source coordinate is available; the observed context is not a guaranteed exact callsite.

Select any service or boundary card to open its inspector beside the diagram. The graph stays in place while you inspect SQL, captured request data or call details. Choose Open code flow for that service's own execution, or View caller for the recorded calling location. Caller actions remain available with HTTP hops hidden. Older captures without a calling location explain what is missing instead of guessing a source line.

Show HTTP hops reveals outgoing HTTP boxes hidden when a matching service segment is present. Service details shows the same request as a nested list. Open Partial evidence for the legend and missing-data notes.

Evidence to inspect highlights recorded failures and missing detail, with links to the owning service or call. It uses the loaded evidence, not a root-cause diagnosis. Expand Capture detail by service for the capture's reported depth; an empty summary does not prove the request is healthy.

Use ← Requests to return to the list, or click the TraceLens logo to go to Live requests from any view.

Explore Code flowSearch, focus & open source›

Code flow shows methods in thread sections; Call tree shows their nesting as a diagram. Expand calls or click a method for inline evidence. The diagram keeps Fit, zoom, Expand all / Collapse all and Fullscreen in view. More contains thread filtering and Overview.

At the top of a service's code view, expand Request data, when present, to inspect captured query parameters and body data. Each section states whether data was captured or omitted. Review this potentially sensitive evidence before sharing a snapshot.

Use Search retained execution evidence in either view to find a class, method, exception type or dependency. Previous match and Next match reveal matches inside collapsed branches. Select a node and choose Focus selected branch to isolate its parents and children. Clear search / focus restores the previous view without changing zoom.

Show source in timeline opens recorded events and available source lines. Live source uses your current checkout; snapshots keep the lines saved with them. Open local source, when available, offers editor links to your current checkout; read its build-mismatch warning before opening. In Timeline / source, the back button, view tabs and Timeline view filter stay visible as you scroll. The filter can show only boundaries and exceptions. Use ↑ Top to return to segment details and Observed external boundaries.

Large traces load a bounded timeline page at a time; use Previous page and Next page. SQL and request values load when expanded. Overview capture keeps request and dependency evidence; Methods adds method events without line events; Methods + lines adds line events. All levels apply within configured scope and limits; SQL and request values are separate opt-ins. Missing, expired or budget-omitted detail is shown explicitly and cannot be recovered by paging.

Use ← request flow to return. Search covers the bounded execution view, not every raw event. Check the searchable/omitted counts and Partial evidence: expanding hidden nodes cannot restore omitted evidence.

Scheduled jobs & ErrorsBackground runs & captured failures›

Scheduled jobs keeps background runs separate from Live requests. Filter by job name, service, time or outcome, then expand a group to inspect a run.

Errors groups captured failures. Narrow by error category, HTTP status or exception class, then expand a group to choose a request. Use the Channel filter to find scheduled-job failures.

Performance insightsSlow SQL & repeated-query evidence›

Open Performance insights, choose recent captured requests or a saved capture, then choose Analyze. API path and time filters narrow recent requests; each run reads at most ten matching requests. Adjust the query thresholds before running again.

Filter findings by slow queries, repeated queries, suspected N+1 or query-heavy segments. Open a request or choose Open query evidence to inspect the recorded SQL and calling context. Suspected N+1 is a heuristic, not a confirmed defect; repeated queries can be intentional.

Read the analysis timestamp, scan counts and warnings. Results do not refresh automatically. Missing SQL or partial captures can hide findings, and cumulative query time is not request elapsed time. This is local/dev investigation of captured evidence, not continuous high-traffic monitoring.

Save, compare & search capturesBefore / after evidence & saved results›

Choose Save snapshot on a request or in its row's Details. Reopen it in Saved captures; it is fixed evidence, not live data. Viewer file identifies a saved snapshot. For an older Browser only capture, choose Save to viewer first.

Open Saved captures, select two viewer captures (Before first), then Compare selected. Review the pair and choose Compare saved snapshots. You can also open Compare & search saved captures → Compare snapshots and choose a Baseline snapshot (Before) and Candidate snapshot (After). Review response and call changes side by side, select a finding, or use Find in these two captures. Changed methods are grouped under their recorded parent where supported. Evidence links open the saved invocation; Back to comparison restores your comparison context. All differences contains detailed counts. Check comparability first: a missing observation is not proof of removed code or a skipped call, and one timing difference is not a benchmark.

Choose Search saved evidence to find a class, method, exception type or destination across saved files. Open a matching snapshot and review reported search limits; no match does not prove code was unused. Use with CLI/MCP offers an explicit minimized copy for other tools; it leaves the original unchanged. Review its privacy note before creating a copy.

Share / export offers Copy snapshot link, Copy live request link and Download graph JSON. Links point to this viewer, not a public sharing site. Saved views remembers filters only.

Large saved captures also offer Download capture archive. In Saved captures, use Import capture archive to reopen that ZIP as a new saved capture without reading live services. Review potentially sensitive request data, SQL and source before sharing archives.

Can't find a request?Check capture readiness & watch a reproduction›
  1. Check the service status beside the TraceLens logo, then choose Refresh or Show latest requests if available.
  2. Check the selected tab: API calls are in Live requests, background runs in Scheduled jobs and snapshots in Saved captures.
  3. Search the API path rather than the browser page URL. Broaden the Time window, remove filter chips or choose Show all retained when the list is empty.
  4. Open Capture info to check what is available. Filters and Refresh cannot recover expired or uncaptured requests.

For a fresh reproduction, open Start an investigation on Requests. Enter the exact Backend path, optionally narrow by method, service, user or site, and choose Check capture readiness to check capture settings and look for existing traces. This does not diagnose application bugs.

An empty Live requests list offers Check capture for this API and Capture my next reproduction. These prepare a draft only. Review and confirm its exact path and filters before checking or watching; a list substring is not an exact backend path.

Select a 60- or 120-second Watch window and choose Watch next request & save. Wait for Watching, then reproduce one matching action in your application. Only one completed, unambiguous new match is saved; review its warnings. Cancel watch, closing the panel or leaving the view stops the watch. This does not enable recording or replay your request.
