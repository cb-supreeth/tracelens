Before you start

TraceLens adds tracing to an application that already works locally.

  • 01

    Run the selected services locally first

    Use each selected service's normal native setup. If cb-app is selected, use Java 8. Confirm the selected services start successfully without TraceLens.

  • 02

    Try the flow you want to trace

    Use your normal local login or API authentication and reproduce the flow. Have its required database, cache, downstream services and test data ready.

  • 03

    Check each selected service

    EMS and Plans use Java 21; Ledger and Grant Orchestrator keep their existing application runtime / Tomcat launcher. If the flow calls a downstream service, connect its caller to it locally and verify the flow first.

  • 04

    Have your source paths ready

    Use the local checkouts matching your running application builds so the displayed source lines are meaningful.

Confirm once, then configure. Apps do not need to stay running during setup. Stop/restart them deliberately when attaching tracing; do not launch duplicate instances. Opening this page or saving settings does not build apps, provision dependencies or restart services. Optional service actions require a separate review after saving.

  5. Inspect evidenceConfirm the expected request, services and detail; read partial-evidence warnings. Missing evidence is not proof of non-execution. For jobs, use Scheduled jobs and save the observed run.

Optional: start or restart selected services

Configuration is saved first. Only a supported launcher or a verified setup-managed process can be controlled here. Stop an existing unmanaged instance manually before its first managed Start; this page will not kill a process merely because it uses a port. Managed launches use the current bundle. For a manual restart, update your agent JAR to the current bundle to use Methods capture.

Restarting interrupts requests and loses in-memory traces. Saved captures are retained. Save any traces you need before continuing.
